# Issues & improvements — 2026-09-08

Tracking doc for a cross-repo pass over `@rniverse/utils`, with knock-on changes
in `@rniverse/connectors` and `aham`. Two halves:

- **Part A** — helpers that `connectors` / `aham` each re-implement; hoist into `utils`.
- **Part B** — correctness / hardening issues inside `utils` itself.

Nothing here is a behaviour change for a *correct* caller except where called out
(logger output format in production; context API surface).

---

## Part A — shared helpers to add to `utils`

| Helper | Re-implemented in | New home | Notes |
|---|---|---|---|
| `retry()` | `connectors` — identical retry loop in all 4 `health()` methods | `lib/utils/retry.ts` | predicate-based (retries on thrown error *or* a caller-defined "bad result"); linear backoff by default |
| `duration.toSeconds()` / `.toMs()` | `aham/src/utils/duration.util.ts` | `lib/utils/duration.ts` | compact strings `<int><s\|m\|h\|d\|w\|y>`, `1y = 365d`; verbatim move |
| `password.hash()` / `password.verify(plain, digest)` | `aham/src/utils/password.util.ts` (exists only to flip argon2's arg order) | `lib/utils/password.ts` | `utils` currently exports raw `argon`; add a normalised wrapper, keep `argon2` export for escape hatch |
| `randomToken(bytes=32)` / `sha256hex(value)` | `aham/src/utils/token.util.ts` (`random`, `digest`) | `lib/utils/crypto.ts` | pure Web Crypto, no app deps; `aham` keeps `sign/verify/jwks` (those need `config`) |
| `Result<T,E>` + `ok()` / `err()` | `connectors` types `{ ok: true as const, … }` inline in every `ping()`/`health()`; `aham` has its own `ok()` | `lib/type/result.type.ts` + `lib/utils/result.ts` | `ok()` / `ok(data)` overload matches `aham`'s existing shape |
| `sanitize(obj, keys?)` / `mask(obj, keys?, maskWith?)` | `aham/src/utils/index.ts` (`sanitize` only) | `lib/utils/sanitize.ts` | `sanitize` = omit keys; `mask` = replace values at keys (deep, key-name match); both parameterised |
| logger reads `LOG_LEVEL` via raw `process.env` | `lib/utils/logger.ts` | — | switch to `environment.get('LOG_LEVEL', 'info')` (dogfood the new helper) |
| **HTTP client with context propagation** | new | `lib/utils/request.ts` | `createClient({ baseURL })` + `http`; auto-adds `x-request-id` / `x-user-id` from `cxt$req`; JSON in/out; `HttpError` on non-2xx; `timeout` + `retry` (idempotent on net-err/5xx); `propagate:false` for external calls. `contextHeaders()` + `seedFromHeaders()` for the receiving side |

### API sketches

```ts
// retry.ts
type RetryOutcome<T> = { ok: true; value: T } | { ok: false; error: unknown };
type RetryOptions<T> = {
  attempts?: number;                                   // default 3
  delay?: number | ((attempt: number) => number);      // ms before retry N (1-based); default n => 1000 * n
  retryIf?: (o: RetryOutcome<T>, attempt: number) => boolean; // default: (o) => !o.ok  (retry on throw)
  onRetry?: (o: RetryOutcome<T>, attempt: number, delayMs: number) => void;
};
function retry<T>(fn: () => T | Promise<T>, options?: RetryOptions<T>): Promise<T>;
// exhaustion: last value returned as-is; a final thrown error is re-thrown.

// duration.ts
export const duration: { toSeconds(input: string): number; toMs(input: string): number };

// password.ts
export const argon2: typeof import('argon2');
export const password: {
  hash(plain: string): Promise<string>;
  verify(plain: string, digest: string): Promise<boolean>;
};

// crypto.ts
export function randomToken(bytes?: number): string;          // base64url
export function sha256hex(value: string): Promise<string>;    // hex

// result.type.ts
export type Result<T = unknown, E = unknown> = { ok: true; data: T } | { ok: false; error: E };
// result.ts
export function ok(): { ok: true };
export function ok<T>(data: T): { ok: true; data: T };
export function err<E>(error: E): { ok: false; error: E };

// sanitize.ts
export function sanitize<T extends object>(obj: T, keys?: string[]): Partial<T>;   // default ['password','hash','token']
export function mask<T extends object>(obj: T, keys?: string[], maskWith?: string): T; // default '***'
```

## Part B — `utils` correctness / hardening

### B1. `context/req.context.ts` — async context on `enterWith`

**Problem.** The hot path (`withRequestId`, used by `aham`'s log middleware) and
`setUserId` / `setRequestContext` all use `AsyncLocalStorage.enterWith()`, which
mutates the current async context *and every child, with no scope exit*. Node docs
flag it as "not recommended … hard-to-track bugs". The safe primitive, `run()`, is
only used by scripts (`runWithContext`). Every `run()`-based isolation test passes;
the `enterWith` path has **no concurrency coverage**.

**Risk.** Cross-request bleed of `requestId` / `userId` under load — rare,
non-deterministic, mislabelled logs that are near-impossible to trace. Also
`setUserId` replaces the store object, so an async child holding the old reference
keeps seeing stale data.

**Fix.**
- Make `run()` the only way a store is established.
- Elysia can't wrap `next()`, so isolate at the fetch boundary: `bindFetch(handler)`
  returns a handler wrapped in `run()` with a fresh store. `aham` switches its
  bootstrap to `Bun.serve({ fetch: cxt$req.bindFetch(app.fetch) })`.
- `set(key, value)` / `patch(values)` mutate the **existing** store in place — no
  second `enterWith`, consistent for any reference holder.
- Drop `getContext()` (raw ALS leak); `getContextValue` → `get(key)`; keep
  `getRequestId()` / `getUserId()` as thin typed accessors.
- Add a concurrency test that exercises the Elysia-style path (`bindFetch` + interleaved awaits).

**API delta** (breaking for our code only; call sites updated in this pass):

| old | new |
|---|---|
| `cxt$req.withRequestId(custom)()` | handled by `bindFetch`; middleware uses `cxt$req.patch(custom)` |
| `cxt$req.getContextValue('k')` | `cxt$req.get('k')` |
| `cxt$req.setUserId(id)` | `cxt$req.set('userId', id)` |
| `cxt$req.getContext()` | removed |
| `runWithContext(fn, custom)` | unchanged (already `run()`-based) |

### B2. `logger.ts` — pretty + sync in production

**Problem.** `export const log = createLogger()` builds a `pino-pretty` stream with
`sync: true` and no `NODE_ENV` gate. Sync pretty printing **blocks the event loop
per log line**; `pino-pretty` is explicitly not for production.

**Fix.**
- Pretty + `sync` only when `NODE_ENV === 'test'` or stdout is a TTY; otherwise
  plain newline-delimited JSON (pino default).
- Add `redact` with a default deny-list (`password`, `*.password`, `authorization`,
  `*.authorization`, `token`, `*.token`, `secret`, `*.secret`, `req.headers.cookie`).
- Pass `customLevels` (`log: 25`) into the pretty stream too, so `LOG` lines render
  with a label.
- `level` from `environment.get('LOG_LEVEL', 'info')`.

### B3. Barrel side effects + no subpath exports

**Problem.** `import { environment } from '@rniverse/utils'` transitively loads the
pino pretty stream, 31 `dayjs.extend()` calls, `argon2` (native build), `jose`, all
of `undici`, and the `String.prototype` patch — because `lib/index.ts` is
`export *` over side-effecting modules and `package.json` only exposes `"."`.

**Fix.** Add an `exports` map with subpaths: `./env`, `./logger`, `./context`,
`./datetime`, `./crypto`, `./retry`, `./result`, `./sanitize`, `./duration`,
`./id`, `./generic`, plus `"."` for the (still side-effecting) full barrel.
`connectors` then imports `@rniverse/utils/env` + `@rniverse/utils/logger` only.

### B4. `string.patch` is not actually opt-in

**Problem.** The comment says "opt-in via `import '@rniverse/utils/lib/patch'`", but
`lib/index.ts` does `export * from './patch'`, so any root import mutates
`String.prototype.fmt`.

**Fix.** Remove `./patch` from the root barrel. Export `fmt` (the standalone) from
a normal module; the prototype patch stays behind an explicit
`@rniverse/utils/patch` subpath only.

### B5. `jose.ts` — hardcoded fallback secret

**Problem.** `JWT_SECRET = process.env.JWT_SECRET || 'your-secret-key-change-in-production'`.
Tokens signed with a public constant if the env var is unset → forgeable. The
`jwt$` / `sign` / `verify` helpers are hardcoded HS256-with-shared-secret, which
`spec.md §2` calls incompatible with `aham`'s RS256 + JWKS design; nothing uses
them except their own test.

**Fix.** Removed `jwt$` / `sign` / `verify` / `getSecretKey` / `JWTSignOptions`
and `test/jwt.test.ts` entirely. `jose.ts` is now just `export const jose = jwt`
— no secret, no `JWT_SECRET`, no footgun. Consumers use the `jose` library
directly.

### B6. `argon2` is a hard dependency

**Problem.** Native (node-gyp) build forced on every consumer; `connectors` never
hashes a password.

**Fix.** Move `argon2` to `optionalDependencies` (or `peerDependencies` +
`peerDependenciesMeta.optional`). `password.hash/verify` throw a clear error if
it's not installed.

### B7. `datetime.ts` — 31 eager plugins, extensionless imports

**Problem.** Every `.extend()` runs on first import of *anything* in the barrel.
The `import … from 'dayjs/plugin/x'` specifiers also lack `.js`, which breaks plain
Node ESM resolution of the built `dist` (seen in the earlier dist review).

**Fix.** Add `.js` to every `dayjs/plugin/*` specifier. Split into a default set
(utc, timezone, customParseFormat, advancedFormat, relativeTime, duration,
isSameOrBefore/After, isBetween) loaded eagerly and the rest behind an opt-in
`date.extendAll()` — or at minimum move `datetime` behind its own subpath (B3) so
only date users pay for it.

### B8. Minor

- `generic.ts` `isBun()` returns `string | true | undefined` — wrap in `!!`.
- `TRequestContext` is all-`any`; give `requestId` / `userId` real types, keep an
  index signature for extras.
- `undici.ts` re-exports the whole namespace — leave, but note it in B3's subpath split.

## Consumer migration

### `connectors`
- `health()` in all 4 connectors → `retry(() => this.ping(), { attempts, retryIf, onRetry })`; keep the `if (!ok) await this.close()` tail.
- `ping()` / `health()` return types → `Result<…>` from `@rniverse/utils`.
- Imports switch to subpaths: `@rniverse/utils/env`, `@rniverse/utils/logger`.
- `.env.sample` already documents `INSTANCE_NAME`.

### `aham`
- Delete `src/utils/duration.util.ts`; `config.ts` imports `duration` from `@rniverse/utils`.
- Delete `src/utils/password.util.ts` (unused elsewhere) or reduce to a re-export.
- `src/utils/token.util.ts` keeps `sign/verify/jwks`; `random` / `digest` delegate to `randomToken` / `sha256hex`.
- `src/utils/index.ts` re-exports `ok` / `sanitize` (+ new `mask`) from `@rniverse/utils`; keeps `ipOf` / `userAgentOf` / `metaOf`.
- `src/middlewares/log.middleware.ts` — `withRequestId` → `cxt$req.patch(...)`; `getContextValue` → `get`.
- `src/index.ts` — `listen()` switches to `Bun.serve({ fetch: cxt$req.bindFetch(app.fetch), port })` so the request context is established via `run()`.
